# Stage 4H.14 — AI Response Labeling & Transparency

## Purpose

Make it explicit when an individual response has been processed by the controlled AI semantic-analysis pipeline.

## Contract

`CommentOut.ai_analysis_status` is one of:

- `pending` — queued for semantic analysis; not evidence for semantic aggregates.
- `analyzed` — successfully processed by the controlled semantic-analysis worker.
- `failed` — analysis was attempted but did not produce a valid stored semantic result.
- `null` — no intelligence record is available for the response.

The frontend displays a distinct **AI analyzed** badge only for successfully analyzed responses, with separate processing/failed states where applicable.

## Safety / provenance

- The badge identifies processing provenance; it does not mean the response is true, authoritative, verified, or generated by AI.
- Human-authored responses remain the underlying evidence.
- AI analysis is a derived annotation used for aggregate intelligence.
- Pending and failed responses are excluded from semantic evidence counts.
- No provider prompt, raw provider payload, participant identity, or hidden model output is exposed.
- No database migration is required; this is a response-contract and UI transparency change.
