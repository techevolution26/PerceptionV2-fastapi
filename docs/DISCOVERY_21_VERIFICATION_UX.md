# Discovery 21 — Verification UX

## Objective
Make professional verification a clear trust signal without turning it into a dominant social badge or implying that verification certifies every statement.

## Product rules
- Professional identity and verification remain separate signals.
- Verification is optional.
- Eligibility and approval are separate: plan eligibility permits application; super-admin review determines approval.
- The verified state is authoritative from `verification_status == VERIFIED`.
- A badge does not certify every statement or convert community observations into scientific proof.
- Review notes remain available to the applicant.
- Pending applications are not resubmitted through the normal application path.

## UI hierarchy
1. Explain the purpose in one sentence.
2. Show current application state prominently but quietly.
3. Keep evidence/context secondary.
4. Keep the skip path visible during onboarding.
5. Avoid adding verification UI to the Home discovery hierarchy.
